01 · 問題

AI 很會聊，但沒有手

你寫好了兩個完全正常的函式：查菜單、下單。人類工程師看一眼就會用， 但 AI 對它們視而不見——它不知道這些函式存在、不知道參數要填什麼、 也沒有標準方式呼叫。過去每家把工具接給 AI 都自己發明一套接法， 直到 2024 年底 Anthropic 開源了 MCP（Model Context Protocol）： AI 界的 USB-C，一套協定接所有工具。

FastMCP 就是用 Python 蓋 MCP 伺服器的主流框架 （它的 1.0 版好用到直接被收編進官方 SDK）。這一課我們不背 API—— 直接親手蓋一個 60 行的迷你版，把它的兩個核心魔法拆給你看。

02 · 魔法一

一個裝飾器，換一份說明書

真的 FastMCP 長這樣——這幾行就是一個完整可上線的 MCP 伺服器：

from fastmcp import FastMCP mcp = FastMCP("Demo 🚀") @mcp.tool def add(a: int, b: int) -> int: """Add two numbers""" return a + b if __name__ == "__main__": mcp.run()

魔法全在 @mcp.tool：它讀你的型別提示和 docstring， 自動生成一份 AI 看得懂的 JSON Schema「說明書」——參數叫什麼、什麼型別、 哪些必填，你一個字都不用多寫。

右邊我們用 inspect 重現了這個裝飾器。掛上去之後， 用下拉選單看每個工具自動長出的說明書；然後改改函式的型別提示， 看說明書跟著變。

03 · 魔法二

統一插座：tools/list 與 tools/call

有了說明書，還缺標準呼叫方式。MCP 規定所有工具伺服器都聽同樣兩句話： tools/list（「你有哪些工具？」）和 tools/call（「幫我呼叫這個、參數在此」）。 AI 助理只要會講這兩句，就能用全世界任何一台 MCP 伺服器—— 這就是「USB-C」的意思。

右邊的 handle() 是迷你伺服器的心臟：收 JSON、查註冊表、 用說明書驗參數、執行、回 JSON。注意示範對話的最後一筆—— 漏填參數的請求被說明書直接擋下，你的函式根本不會被執行。 然後換你當 AI：自己送一筆請求進去。

04 · FASTMCP 4

4.0 的招牌：斷線也記得你

新版 MCP 協定是 sessionless：每個請求各自獨立，沒有「保持連線」。 對伺服器超省資源，但問題來了——怎麼記住「這位顧客點過什麼」？ FastMCP 4 的答案是 UserSession：伺服器端幫每個使用者留一個 置物櫃，鑰匙是認證身分，跨請求、跨裝置都開得到同一格。

到右邊拉「重播」滑桿：小明和小美的請求交錯抵達、各自獨立， 伺服器的置物櫃卻始終分得清清楚楚——這就是 無狀態傳輸上的有狀態應用，FastMCP 4 的核心主題。

4.0 一起帶來的還有：

  • 互動工具：工具可以跨請求向使用者追問（多輪往返），不用一次問齊。
  • 背景任務：長工作丟給 fastmcp-tasks 擴充，不用掛著連線等。
  • 企業身分：agent 能以使用者的公司身分行事，免每次跳 OAuth。
  • 新舊通吃：同一台伺服器自動跟新舊兩代協定的客戶端協商。

誠實說明：FastMCP 4 目前是 beta（最新 4.0.0b3），官方建議釘死版本號。 想在自己電腦跑真的：穩定版 uv add fastmcp、 嘗鮮版 uv add "fastmcp==4.0.0b3"， 把第 2 節那段程式存成 server.py 後 uv run server.py 就是一台伺服器。 另外 4.0 移除了 ctx.sample() 與 ctx.list_roots()，升級前先查遷移指南。
